Implementation notes — bounded specular reflection (eval/hy4-reflections)

Task-local reviewer log. Every entry below is transferred to the draft pull request body and to docs/performance/reflections-engine.md.

Decisions not explicit in the specification

  1. How a fragment learns it is reflective. The specification requires a material/reflection API but not how a fragment binds to a material. Chosen: the mirror strength is the w component of the reflection palette entry for the authoritative voxel material at floor(p - n * SURFACE_OFFSET), read from the source volume. Rationale: adds no field to matterweave_core::Vertex (which would touch core meshing, detail, physics, gallery and four examples), and ties reflectivity to authoritative world data rather than to derived mesh attributes. Consequence: dynamic meshes, static instances and detail geometry are neither reflective nor reflected, and a reflective face on the outward shell of the source volume terminates as a miss.
  2. Equal-revision scene replacement. RayVolume::valid_for compares epoch, revision and seed only, so a replaced scene at an unchanged revision would be accepted if the caller kept the epoch. The specification requires that it must not be. Added an FNV-1a footprint digest over the volume cells, recomputed at publication. Cost: one World::get per cell (at most 262,144), publication only, never per frame.
  3. Sun handling. The diffuse cache bakes the sun and therefore keys on it; reflections do not bake the sun, so the sun stays a live per-frame uniform and a sun change needs no republication. The specification's "light invalidation" is satisfied by geometry/shadow-resource invalidation plus this recorded difference.
  4. Shadow on the reflected hit. Not applied. A reflected hit uses albedo * (ambient + sun term) only. Recorded limitation: an object in shadow appears fully lit in a mirror. Including it would have made the CPU oracle depend on rendered shadow-map contents and weakened the independence of the agreement test.
  5. Background termination. A ray that leaves the volume, self-intersects, starts outside, meets a zero-length interval, or exhausts the step budget terminates against the scene background/fog colour vec3(0.16,0.24,0.29) at the volume-exit distance — the same colour the fog uses, so a miss and a fully fogged hit agree.
  6. Headless validation compiles the shipping shader. Rather than a second copy of the algorithm, the harness builds the renderer's group-0 layout from a new public shader_contract module and compiles the Naga SPIR-V the Renderer itself uses. This required exposing WORLD_VERTEX_SPIRV, WORLD_FRAGMENT_SPIRV and LightingUniform.

Bounds and tolerances

  • Source volume ≤ 64³ cells, each axis ≤ 64, endpoints within ±8192.
  • Trace steps configurable 1..=512; effective WGSL bound is min(steps, dims.x+dims.y+dims.z+1), so a generous budget cannot lengthen a ray.
  • One secondary ray per reflective fragment; no recursion, no temporal history.
  • Owned GPU bytes: ≤ 1 MiB material grid + 4 KiB palette (reflection_state()). No staging buffer: one host-visible coherent destination buffer per resource, rewritten in place after the frame fence.
  • Tolerances: 3/255 per channel for mirror probes, 1/255 for the nonreflective baseline. Measured worst case 0.00193 (≈0.49/255) and 0.00196 (≈0.50/255); the residual is 8-bit quantisation of the expected value, not model error.
  • Probe "non-edge" filter, registered before any comparison and applied to predetermined probes too: minimum parametric gap between consecutive DDA crossings ≥ 1e-3 and hit clearance ≥ 0.05 cell. All 28 predetermined probes pass the filter, so no probe was excluded after seeing a result.

Deviations and corrections during the work

  • Four initially chosen probe eye offsets produced near-simultaneous DDA crossings (gap < 5e-5). They were redesigned from a numeric search for large crossing gaps rather than excluded; the final 28 all have gaps ≥ 0.195.
  • The first image fixture put a stone wall between the camera and the mirror, hiding the reflection entirely (0 changed pixels). Fixed in the fixture.
  • The first off-screen-removal comparison reused the previously published GPU buffers, so the removal appeared to change nothing. Fixed by republishing; the gate now also asserts that with reflection disabled the removal changes zero pixels, which proves the object is off-screen.
  • clearance initially walked past the volume bounds, reporting spurious near-ties for long miss rays. Fixed by stopping at the volume AABB.

Reviewer risks and follow-ups

  • Cost. The traversal runs per reflective fragment with up to 193 iterations for a 64³ volume. On llvmpipe it roughly doubles frame time; mobile cost is unmeasured. No mitigation (roughness LOD, half-resolution tracing, planar-reflection specialisation) is implemented.
  • Device gates NOT RUN. The shared phone is owner-reserved. Items 10 and 11 of the acceptance list remain pending; the ready-to-run candidate is the --reflection-cost / reflection-check.txt app gate.
  • Reflections omit dynamic meshes, static instances and detail geometry, and omit shadows on reflected hits.
  • The footprint digest makes publication O(cells); for a 64³ volume this is a measurable few milliseconds that is reported as part of request-to-publication latency, not hidden.
  • The shader_contract module exposes shader SPIR-V and the uniform struct publicly for validation harnesses; a reviewer may prefer to gate this behind a feature flag.

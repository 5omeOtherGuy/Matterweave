## Findings (5)

**1. `docs/performance/detail-local-loss-guard.md:48-49` + `src/select.rs:29-31` — "ordinary surface steps never trip it" is false for any non-axis-aligned surface.** Trigger: any sloped, stepped, curved or organic prototype (a wedge with `z <= x`, a sphere, a trunk). Its surface coarse cells are partially occupied *inside* the occupied bbox, so clipping does not rescue them: a diagonal boundary cell with 5/8 occupied reads `0.375 > 0.0`. Consequence: with the default `max_local_loss_fraction = 0.0`, automatic LOD is inert for essentially all non-cuboid content — the exact content class the engine targets — while the doc presents the default as only holding interior openings. Evidence: `worst_interior_loss` (scene.rs:127-152) iterates *all* occupied coarse cells, not interior ones; the clip is only against the global bbox (`min`/`max`), never against local occupancy. No fixture in `tests/local_loss.rs` is non-cuboid (block/tunnel/pit/stem/sheet are all axis-aligned), so the suite cannot detect this. Classification: conservative-quality tradeoff in *behavior*, but an inaccurate claim and a real coverage gap.

**2. `src/scene.rs:166` (via `lib.rs:525-538`) — the metric is occupancy-only, so any non-AIR fill defeats the guard.** Trigger: a tunnel/cavity filled with a liquid or decorative material instead of air (flora/water prototypes). `iter_cells` filters only `material::AIR`, so those cells count as occupied → `count == expected` → `local_loss_fraction = 0` → the level is selected; `coarsen` (lib.rs:~700-712) then collapses the coarse cell to the *majority* material, i.e. the surrounding stone. Consequence: a water channel or leaf pocket is visually filled with the host material at Half/Quarter with no guard signal. Collision is unaffected (`is_collidable_world_metres` reads source). `tests/local_loss.rs:1-8` claims "interior heterogeneous coarse cells hold the prototype at `Source`" — true for occupancy heterogeneity only; material heterogeneity is invisible to both guards.

**3. `tests/local_loss.rs:198-208` — hysteresis leaks across the camera loop, weakening the orthographic assertion.** Trigger: the `for camera in [persp_at(...), ortho_at(...)]` loop reuses one `scene`; after the perspective pass `self.selection` holds `Quarter`, so the ortho pass evaluates against the *high* threshold (`choose_lod`, previous ≥ lod branch) instead of `low`. Consequence: `at("o") == Quarter` under orthographic is partly proven by retained state, not by the ortho projection alone; a regression that made ortho coarsening too strict could still pass. Fix shape: build a fresh scene per camera (as `dense_block_coarsens_far_and_resolves_source_near_with_zoom` already does with its `dense()` closure).

**4. No test pins guard behavior across edits — the per-instance-edit and edit-invalidation path is asserted only indirectly.** `tests/local_loss.rs:296-349` proves selection *doesn't* mutate source, but nothing carves a tunnel via `edit_prototype`/`edit_instance` and re-runs `select_lods` to assert the prototype flips from `Quarter` back to `Source`, nor that one edited instance (`__instance_edit:<id>`, scene.rs:295-345) drops to `Source` while its siblings keep coarsening. I traced the mechanism and believe it is correct (digest keyed by `revision`, scene.rs:558-570; new prototype id ⇒ fresh digest), so this is a coverage gap, not a demonstrated defect. Related minor: `digests` and `selection` are never pruned, which is currently harmless only because no prototype/instance removal API exists.

**5. `src/select.rs` `choose_lod` break + `docs/...:71-74` — an intermediate `max_local_loss_fraction` can be unreachable because loss is non-monotone in coarseness.** Trigger: tunnel prototype with `max_local_loss_fraction = 0.1`; Half reads 0.25 → `break` → `Source`, even though Quarter reads 0.0625 and would pass. Consequence: the documented tuning knob ("callers that can tolerate a specific opening set `max_local_loss_fraction`") behaves discontinuously — for tunnels only `0.0` (Source) or `≥0.25` (Half+Quarter) are reachable. The `break` is the conservative choice and I would keep it; the documentation should state the threshold is applied to the *finest coarse level first*, not per level independently.

No mathematical, overflow, negative-coordinate, empty/sparse, or cache-invalidation defect found in the metric itself.

## Engineering log

- **Actions**: Recomputed every published loss/dilation figure by hand from the fixture geometry; traced `iter_cells → compute_digest → worst_interior_loss → coarse_metric → choose_lod` and the three cache keys (mesh, digest, selection); checked `div_euclid` on negatives, sentinel bbox on empty volumes, u32 footprint overflow, and `expected ≥ count`; audited fixture shape coverage and cross-test state reuse.
- **Issues**: doc/behavior mismatch on surface steps (F1); occupancy-only blind spot to liquid/decorative fills (F2); hysteresis-contaminated ortho assertion (F3); edit-path coverage gap (F4); non-monotone threshold semantics (F5).
- **Decisions**: Treated the strictness of default `0.0` as an intended conservative tradeoff, not a bug; reported only the inaccurate claim and missing coverage around it. Did not report `digests`/`selection` unbounded growth as a standalone finding since no removal API exists.
- **Solutions (not applied, read-only)**: reword the "surface steps" sentence and add a wedge/sphere fixture; either extend the metric to material heterogeneity or scope the docs to occupancy explicitly; fresh scene per camera in the ortho loop; add an edit → re-select regression test.
- **Insights**: The clip-to-occupied-bbox trick is what makes dense cuboids read exactly 0, and it is correct — but it is a *global* clip, so it only neutralizes the prototype's outer box, never local surface staircases. That single property explains both the guard's strength (tunnels/pits caught, boundary case included) and its cost (curved geometry pinned to Source).

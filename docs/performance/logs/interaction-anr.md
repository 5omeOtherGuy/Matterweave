Worker: continuation session (`interaction-anr`) · outcome: Category: debug · status: code/log committed, no push; lead owns device reproduction, PR review and combined Android run.

- **Actions Taken:**
  - Verified the owner hypothesis with measured structural counts from `build_showcase(SHOWCASE_SEED)`: `draws=8302 prototypes=893 chunks=3189`. Resolving bounds per instance via `DetailVolume::bounds_world` re-censuses the shared prototype for every placement: up to 228,188,160 cell reads per action ray, where the 893 distinct sources hold 13,062,144 — the same full censuses ~17.5× over, on the input thread, per ray. `WetlandApp::action` additionally ran this ray for every action including `Throw` (which needs no source query), and PLACE/REMOVE paid it twice (action + `Runtime::edit`).
  - Narrow reusable fix in `crates/matterweave-detail/src/scene.rs` (lead-authorized): `DetailScene::instance_bounds_world(&mut self, instance_id) -> Result<Option<Bounds>>` reuses the existing per-revision `Digest::bounds_local` (already refreshed by production LOD selection in `select_lods`/`DetailRuntime::prepare`) and projects all eight corners through the exact instance transform. Errors on an invalid transform; `Ok(None)` for an empty source or unknown instance. No new cache, no new invalidation rules: `digest()` already keys by prototype source revision, so a COW edit (private `__instance_edit:` fork) or an in-place `edit_prototype` recomputes exactly the changed prototype.
  - Added `DetailScene::digest_builds()` counter (once per prototype revision, lazily) as cache-reuse evidence. Deliberately kept out of `SceneCounts`, whose whole-struct equality is used as a no-authoritative-mutation assertion (`prepare_never_mutates_the_authoritative_scene`); digest warming is derived-cache work.
  - `wetland_state::raycast` now takes `&mut DetailScene` and resolves instance bounds through the accessor (all three production callsites are in `&mut Runtime` methods). Preserved contracts: abort the whole ray on a missing prototype (pre-existing `?` behaviour), skip empty/invalid-transform draws, nearest hit by distance, DDA cell stepping, exposed-face `previous`, decorative/liquid filtering (unchanged traversal code).
  - `wetland.rs`: `Throw` no longer performs any raycast; `Grab`/`Break` share one `Runtime::reach()` ray; `Remove`/`Place` use the single ray `Runtime::edit` already performs (no duplicate action+edit ray).
  - Tests: `wetland_state::tests::action_raycast_resolves_bounds_from_cached_revision_digests` (65 placements of one source → exactly 1 digest build, warm ray stays 1, COW removal edit → hit disappears, edit adding a cell **outside** the previously cached bounds → ray hits the new cell, so stale shrinking bounds cannot pass) and `scene::instance_bounds::instance_bounds_match_bounds_world_and_reuse_revision_digest` + `empty_prototype_instance_bounds_are_none` (exact equality with `bounds_world` under the same transform, growth reflected, only the forked source rebuilt, `Ok(None)` cases). Existing transformed/yawed/negative-coordinate and corner-placement raycast tests unchanged and passing through the new path.
- **Issues & Friction:**
  - Two early cargo invocations were stopped by the lead for omitting `RUSTC_WRAPPER=` / wrong target dir; a release/timing attempt was also stopped. Re-ran everything with the mandated dev-profile prefix (`env RUSTC_WRAPPER= CARGO_BUILD_JOBS=1 CARGO_TARGET_DIR=.../interaction-anr/target`). No timing benchmark was performed; the ANR argument rests on counted structural work (cell reads), not wall clock.
  - An app-side `BoundsCache` prototype was added before the lead authorized the smaller scene-digest route; it was fully deleted (unused `HashMap` import, `MAX_BOUNDS_ENTRIES`, `raycast_cached`, `prime`) in favour of the scene accessor, avoiding a duplicate cache with independent identity semantics.
  - `assert_ne!(edited, unedited)` in the scene test was vacuous (different transforms); lead review required exact same-transform comparison against the edited private source plus an expansion case — fixed as directed.
  - Initial `digest_builds` placement in `SceneCounts` broke an existing explorer equality test in `detail_runtime.rs` (not worker-owned); moving the counter to a dedicated accessor resolved it without touching that file.
  - Clippy `question_mark` lint: an explicit `if … is_none() { return None }` was replaced by `scene.prototype(&draw.prototype)?;` (identical semantics); the `Ok(None) | Err(_) => continue` match keeps the skip-vs-abort distinction that `?` would collapse.
- **Decisions & Rationale:**
  - Scene-digest reuse over a new app cache: zero invalidation logic to get wrong, warmed off-thread by load/selection, and per-revision keying already matches COW fork and in-place edit invalidation exactly.
  - Missing-prototype handling preserved as whole-ray abort (previous behaviour), not per-draw skip.
  - Regression asserts counted digest builds (1 per prototype revision, 0 on warm rays) instead of wall-clock timing, so the eliminated full-scan work is demonstrated without fragile timing assertions.
- **Solutions Applied:**
  - `wetland_state::raycast` aborts on a missing prototype via `?` before the `&mut` bounds call, then re-borrows the volume immutably for the DDA — no borrow conflict, same contract.
  - `instance_bounds_world` clones only the prototype id (already the established pattern in `edit_instance`); per-draw cost is a map lookup plus 8 corner transforms.
- **Insights:**
  - The digest was already computed for every instance every frame by LOD selection; the interaction path was the only consumer still paying per-placement censuses. Reusing an existing warmed cache was both the smallest and the safest fix.
  - Bounds expansions after edits are the dangerous case for any cached-bounds ray: a stale too-small bound silently skips the draw. The regression ray hitting a newly added out-of-bounds cell guards it.

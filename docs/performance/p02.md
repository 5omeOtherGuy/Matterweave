# P02 working candidate: dynamic geometry reuse

Status: CPU cache and transactional app upload reuse implemented; independent
source reviews found no cache regression. A measured diagnostic exposed a larger
WSI recreation hotspot, now fixed under tests. **No matched mobile optimization
win is accepted yet.**

The matched comparison, its phone conditions and the executed result are in
[p02-analysis.md](p02-analysis.md); the collector contract is
[p02-phone-runner.md](p02-phone-runner.md).

## Narrow implementation and integration sequence

1. Preserve the uncached `Physics::dynamic_mesh` reference and all simulation rules.
2. Cache complete ordered interpolated poses, dimensions and materials, not sleeping
   flags, backend handles, or fixed-step revisions. Reuse existing Rapier/glam
   interpolation and `append_box`; a wrapper around the full mesh constructor
   cannot avoid constructing that mesh. Reuse `Vec` capacities, with no new dependency.
3. App integration retains upload-dirty state until upload succeeds and uploads
   retained geometry after renderer recreation even when physics is unchanged.
   Three upload-state tests and normal 90-frame Vulkan lifecycle smoke constrain
   that seam. The native-gallery writer was inactive before integration.
4. Review the frozen change independently, run host/lifecycle regression checks,
   then run same-quality matched phone comparisons. No acceptance based only on
   the existence of a cache or synthetic timing.

Stable identical poses bypass quaternion interpolation to avoid numerical jitter.
The differential geometry tests permit at most 0.0001 difference per position,
normal/color component; topology/index order must match exactly. Physics snapshots
are unaffected. Render-input scratch and geometry capacities are retained; the
reported byte count excludes allocator metadata, owning struct and GPU allocations.
The test ceiling is 256 KiB for the current 64-body cap, not a whole-engine memory budget.

## Actual WSI hotspot and working policy

A separate diagnostic based on P01 (`codex/p02-wsi-probe`, `eb045e5`) added only
bounded logs for 16 captured draws. `device/wsi-probe-02/logcat.txt` contains 80
trace lines: all 16 presents returned `Ok(true)` (SUBOPTIMAL), requested/actual
extent stayed 3168×1440 and the next draw recreated the swapchain every time.
Subsequent sampled draws spent roughly 16 ms between shadow update and finished
swapchain recreation. These are early, instrumented diagnostic observations,
not a warm sustained measurement or an optimization comparison. Probe logs are
NOT in the production candidate.

The [Khronos result contract](https://docs.vulkan.org/refpages/latest/refpages/source/VkResult.html)
says SUBOPTIMAL can still present successfully. Working engineering decision:
defer this advisory to actual resize or OUT_OF_DATE rather than rebuilding the
same swapchain/pipelines every frame. Do not change IDENTITY pre-transform:
compositor-managed rotation is deliberate; claiming a pre-rotated image without
rotating rendering would break output. Periodic futile reconstruction adds work;
changing rotation/rendering is a larger, unneeded alternative for this fix.
